Design principle
PulseOps should feel like a calm control room, not a red emergency screen. Red is the brand/action accent; green, amber, blue and neutral states keep system status readable.


1. Executive UI/UX Direction
PulseOps is a technical monitoring product, so the interface should prioritize information density, hierarchy and fast scanning. The visual language uses a dark slate foundation, high-contrast white typography, restrained borders and a bright red primary accent. The motion language borrows the supplied reference video’s cinematic qualities—deep dark atmosphere, soft particle movement, centered focal content, staged text reveals and gentle depth—without copying its space/cosmos visuals literally.
Default mode: dark only for the first release; light mode can be added later without changing component semantics.
Tone: precise, technical, calm, premium and slightly cinematic.
Density: dashboard-first; cards should contain enough data to be useful but never feel crowded.
Motion: purposeful and restrained. Animations should explain state changes, guide attention or establish product identity.
Brand color discipline: use the red/pink primary for actions, active navigation, critical attention and brand moments—not for every chart or status.

8. Add-Service Journey
The Add Service flow is the key bridge between the customer’s application and PulseOps. It must be simple enough for the MVP and explicit enough that a developer understands what is being connected.
1. Open Services → Add Service.
2. Choose service name and environment (Development / Staging / Production).
3. Show the monitoring connection step with the exact endpoint/configuration needed by the demo app.
4. Test connection and show immediate result: Connected, Warning or Failed.
5. On success, create the service record and open its detail page.
6. Offer “View Overview” and “Open Logs” as the two most useful next actions.

10. Homepage Animation Direction
The supplied motion reference uses a dark atmospheric field, slow particle drift, centered UI cards, large editorial typography and staged transitions. PulseOps should translate those qualities into a technical monitoring context rather than a space theme. The motion should feel like telemetry coming alive: subtle particles or data points in the hero, a soft focus shift, then a crisp dashboard/product reveal.

13. Accessibility and UX Safety
Do not communicate severity by color alone; pair each status with text or icon.
Keyboard focus must be visible for all buttons, links, fields and sidebar navigation.
Charts need textual summaries for key values.
Loading states must reserve space to prevent layout shift.
Destructive actions such as delete/disable must have confirmation and clear consequences.
Errors should be local to the failing field when possible and global only when the whole action failed.

15. Design Do / Don’t
Do
Don’t
Use dark slate surfaces with subtle hierarchy.
Use pure black + pure white everywhere.
Use red for brand/action/critical emphasis.
Color every chart and every success state red.
Use cinematic motion on the landing page.
Use looping glow/particle animation behind operational data.
Keep dashboard interactions immediate and quiet.
Make operational screens behave like a marketing page.
Show evidence beside AI conclusions.
Let AI present unsupported guesses as facts.
Design empty, loading and error states intentionally.
Treat them as afterthoughts.

16. Final UI/UX Implementation Priority
1. Lock tokens: colors, typography, radius, spacing, shadows.
2. Build the authenticated shell: sidebar + top bar + routing.
3. Build Overview dashboard with static mock data.
4. Build Services + Service Detail.
5. Build Incidents + Incident Detail.
6. Build Alerts, Metrics and Logs.
7. Add Add-Service onboarding flow.
8. Add AI Assistant shell and evidence links.
9. Add homepage cinematic animation and hero product reveal.
10. Run responsive, accessibility and state reviews before backend data is wired.

17. UI/UX Acceptance Criteria
•  A new user understands the product purpose quickly and can reach the main dashboard without confusion.
•  Overview, Services, Incidents, Alerts, Metrics and Logs are reachable in one click from persistent navigation.
•  Service and incident detail screens preserve context and link directly to related logs, metrics and evidence.
•  Primary, secondary and destructive actions look and behave consistently across the product.
•  Landing motion is cinematic; operational screens remain calm, fast and readable, with clear loading, empty, error and success states. Color is never the only source of meaning.
